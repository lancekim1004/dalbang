## 알아둘 점
- **사이트 주소:** https://dalbang.vercel.app — GitHub `main`에 올리면 Vercel이 자동으로 다시 배포함.
- **Vercel 환경변수:** `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` + (2-1부터 필요) `SUPABASE_SECRET_KEY`. 비밀 키는 Vercel 화면에 직접 넣고 Sensitive 켜기.
- **예약 저장 구조:** 방문자 화면은 공개 키로 읽기만. 예약 저장·조회는 서버 액션(`src/app/booking/actions.ts`)이 비밀 키(`src/lib/supabase/admin-client.ts`)로 처리.
- **관리자 계정 만들기(사용자):** Supabase → Authentication → Users → Add user로 만든 뒤, admins 표에 그 사용자를 추가 (방법은 README/안내 참고).
- 시험용 예약 `DB-JLJPXY`(test-request@example.com)가 DB에 남아 있음 (2026-10-24 브라우저 시험).
- **GitHub 도구:** `gh`가 `~/.local/bin/gh`에 설치·로그인돼 있음 (계정 lancekim1004).
- **Next.js 16.4** 사용. 예전 버전과 다른 점이 많아 코드 작성 전 `AGENTS.md` 안내대로 `node_modules/next/dist/docs/`를 확인할 것.
- 새 캐시 기능(`cacheComponents`)은 **꺼 둠** — 초보자 관리가 쉬운 기존 방식 사용.
- 데이터는 Supabase DB에서 읽음. 화면은 모두 `src/lib/repo.ts`를 통해서만 가져옴. 방문자 화면은 **공개 키**로 읽어서 RLS가 숨긴 자료를 자동으로 걸러냄.
- DB 명령: `npm run db:push`(새 마이그레이션 적용), `npm run db:types`(표 구조 → TypeScript 타입 다시 만들기). 비밀번호는 `.env.local`에서 읽고 화면엔 가려짐 (`scripts/supabase-db.mjs`).
- 예시 자료 다시 넣기: `node scripts/supabase-db.mjs db push --include-seed` (같은 ID라 중복 안 됨).
- 새 Supabase 프로젝트는 표 권한을 자동으로 안 줌 → **새 표를 만들면 RLS와 함께 GRANT(표 권한)도 마이그레이션에 넣을 것.**
- 데모 예약은 seed를 실행한 날 기준 상대 날짜(3일 뒤 등). 시간이 지나 달력이 비면 seed를 다시 실행. 데모 예약 금액은 0원(데모 표시).
- 방·숙소 주소가 UUID(긴 고유번호)로 바뀜 (예: `/rooms/cffec1dc-...`).
- DB는 **서울 지역**(ap-northeast-2). 연결 주소는 `aws-0-ap-northeast-2.pooler.supabase.com`.
- Supabase 새 프로젝트 만들 때 지역은 `Need a specific region?`을 눌러야 서울을 고를 수 있음 (그냥 Asia-Pacific은 싱가포르).
- 지도(OpenStreetMap)의 지명은 **한국어**로 나옴. 영어 지명 지도는 3단계에서 무료 대안 검토.
- 날짜 입력칸 모양(예: 연도. 월. 일.)은 보는 사람 브라우저 언어를 따름 — 외국인에게는 자기 언어로 보임.
- 예약 요청 버튼은 2단계 전까지 비활성(회색) 상태.
- 사진은 Unsplash 무료 사진(외부 주소). 실제 운영 시 Supabase 사진 창고로 교체.
